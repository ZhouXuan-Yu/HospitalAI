# HospitalAI AI Service(ai-service)规范

> ai-service 是 FastAPI 服务,仅负责上下文辅助整理、文档解析、检索、重排序和解释草稿。它不是决策者,是检索与解释的辅助层。

---

## Pre-Development Checklist

动手改 ai-service 代码前,必须完成:

1. **先读共享指南**:`../../guides/index.md`(尤其医学安全边界)。
2. **确认职责边界**:这个改动是否越过了"辅助整理/检索/解释"的职责?是否碰了过敏确认、剂量、审核状态、正式处方?
3. **降级设计**:失败时如何降级?是否保留基础事实与硬规则结果?
4. **确定性**:统计是否走固定代码?解释是否只基于已检索证据?
5. **契约**:与 core-api 的 OpenAPI 契约是否变更?

---

## 职责边界(硬约束)

ai-service **只能**做:

- 上下文辅助整理
- 文档解析
- 检索(元数据过滤、关键词/向量)
- 重排序
- 解释草稿

ai-service **绝对不能**:

- ❌ 确认过敏
- ❌ 发布医学规则
- ❌ 生成确定性剂量
- ❌ 改变正式审核状态
- ❌ 直接写正式处方

---

## 技术栈

- FastAPI + Pydantic 模型。
- 与 Java core-api 通过明确、版本化的 OpenAPI 契约通信。
- 模型调用必须经过统一网关。没有密钥时应使用**确定性模拟实现并明确标注**,不得假装完成了真实模型验证。

---

## 检索流水线

固定可审计流水线(与业务核心一致):

```text
metadata_filter → keyword_recall → vector_recall → rerank → explanation_draft
```

- 找不到依据时明确显示"证据不足",**禁止补写理由**。
- 模拟或未审核资料必须显示"演示证据/未发布"。
- 推荐结果必须保存证据来源和审核记录。

---

## 统计纪律

- 科研统计使用**固定 Python 分析代码**,不允许模型自由生成统计结果。
- 统计输出保留稳定哈希(输入/输出),用于可复现与审计。
- 统计结论必须附局限性声明(如 `descriptive_statistics_only`、`not_publication_ready_without_human_review`)。
- 关键变量缺失时标记缺失,不得把未知值当正常值。

---

## 降级设计

- AI 服务失败时,基础患者上下文和确定性安全审查仍可用。
- 证据检索失败返回 `degraded` 状态,保留硬规则结果,**禁止补写理由**。
- 所有降级路径都要有明确状态码与解释。

---

## 测试要求

- Python 单元测试。
- 检索降级测试(网络失败、无证据、证据不足场景)。
- 解释草稿测试(不得在无证据时生成理由)。

---

## 评审清单

- [ ] 是否越过职责边界(过敏/剂量/审核/处方)?
- [ ] 无证据时是否禁止补写理由?
- [ ] 模拟证据是否标注"演示证据/未发布"?
- [ ] 统计是否固定代码 + 稳定哈希?
- [ ] 失败是否明确降级而非假装成功?
- [ ] 契约是否与 core-api 对齐?
