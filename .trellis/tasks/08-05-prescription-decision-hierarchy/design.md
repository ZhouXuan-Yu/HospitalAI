# Design: 处方辅助决策页面主次层级与 DeepSeek 流程优化

## Scope

调整 `apps/web/src/views/DoctorWorkbench.vue` 与对应全局样式，使处方推荐结果成为页面第一视觉焦点。保留现有 `useWorkbenchStore.load/decide` 数据流，不新建后端契约。

## Layout

- 三栏仍为主结构：左侧患者输入/摘要、中央推荐与处理、右侧风险/证据参考。
- 默认比例改为左右约 20%、中间约 60%。
- 左右侧栏支持收起为窄栏，保留图标、标题和关键计数，点击后展开。
- 用背景、留白和阴影区分区域，弱化硬分隔线。

## Content Hierarchy

- 中央默认展示推荐结论卡：推荐方案、主要理由、风险状态、监测要点、操作按钮。
- 候选对比、推理阶段、证据链默认放入可展开详情，避免压过核心结论。
- 左侧常驻患者主诉/诊断摘要；检验、用药、过敏/病史等细节折叠。
- 右侧常驻风险总览；完整风险、证据、缺失数据通过标签和侧栏展开查看。

## Flow

- “生成/刷新推荐”调用现有 `load()`，从当前患者数据重新加载 Core API 或预览数据。
- “模拟患者”切换工作列表中的下一条记录，触发完整加载流程。
- 医生采纳/修改/驳回继续调用 `store.decide`，由真实 Core API 或预览流程处理。

## Constraints

- 不绕过硬阻断；禁用状态继续由 `store.hasBlockingRisk` 和候选 `blocked` 决定。
- 不新增装饰性元素；动画只用于核心加载状态和命中推荐结果。
- 保留 `data-testid="doctor-workbench"`，不破坏现有 e2e 入口。
