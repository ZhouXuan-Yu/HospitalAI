# 医疗药学工作台前端重塑实施计划

## 实施顺序

1. 审计当前 AppShell、router、workbench/dataAccess、五个相关 view 和现有 OpenAPI，列出可复用字段与缺口。
2. 建立接口 MD：先写页面、请求、响应、状态、错误和权限，再按文档实现 UI 消费路径。
3. 改造 AppShell：横向角色导航、角色过滤、左侧业务列表壳、全局任务徽标和数据边界标识。
4. 抽取共享的页面局部结构：折叠侧栏、详情面板、风险条、空状态、任务行和底部操作区；不新增全局 store。
5. 重塑医生处方推荐：患者列表、候选摘要、右侧药品/风险/证据详情、对比模式和决策操作栏。
6. 重塑药师处方审核：科室待审列表、长期医嘱每日复审、单医嘱/联合用药标签、批量审核限制和患者详情。
7. 补齐处方点评、药历、用药教育：统一患者上下文入口，分别实现治疗周期、重点患者药历和教育任务状态。
8. 衔通知识库和科研：知识版本状态回链到风险提示，点评/结局/药历进入科研候选，科研报告进入知识审核。
9. 增补单测和 Playwright：角色过滤、侧栏展开、硬阻断、长期医嘱、审核、点评、药历、教育、科研跳转和降级状态。
10. 运行构建、单测、两视口 E2E、依赖审计、需求追踪检查和手工视觉审查。
11. 更新 `Memory.md`、需求追踪、验收报告和接口文档，保留用户已有未识别脏改动，不回滚、不纳入提交。

## 验证门禁

- `npm run build`
- `npm test`
- `$env:E2E_BASE_URL='http://127.0.0.1:5176'; npm run e2e`
- `npm audit --registry=https://registry.npmjs.org`
- `git diff --check`
- 1366×768 与 1920×1080 页面截图和横向溢出检查
- 至少验证正常、硬阻断、长期医嘱、缺失信息、知识库降级和权限过滤场景

## 交付物

- 可运行的角色化前端工作台
- 处方推荐、处方审核、处方点评、药历、用药教育页面链路
- 知识库和科研数据分析前端入口
- 前后端接口数据契约 MD
- 需求追踪矩阵、审查报告、测试报告和验收结论
