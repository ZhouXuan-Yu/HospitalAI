# 医疗药学工作台前端重塑设计

## 1. 设计边界

本任务只改造 `apps/web` 前端体验和前后端接口说明文档，不改动 Java Core API、FastAPI、数据库或医院连接器。前端正式模式继续通过 `coreApi` 读取后端状态，预览模式只作为导入验证数据的降级路径，界面必须持续标明数据边界。

## 2. 现有架构复用

- `AppShell.vue` 继续作为唯一应用壳，承载横向导航、角色过滤、全局错误和场景导入入口。
- `workbench` store 继续负责 Core API 服务端状态和医生处方决策。
- `flowSimulation` store 继续负责前端验证流程、跨页面共享和 revision 通知。
- 页面仍使用 Vue Router 懒加载，页面级状态保留在对应 view，跨页面状态只进入现有两个 store。
- 共享 UI 通过 `components/` 增加，不引入第三个全局 store。

## 3. 页面与状态边界

### 3.1 全局应用壳

新增角色化横向导航模型：医生默认显示处方推荐、我的患者、用药追踪；药师默认显示处方审核、处方点评、药历、用药教育、知识库、数据分析。导航根据开发角色头或真实身份响应过滤，不提供前端越权切换。

### 3.2 共享工作台框架

以共享 CSS 类和页面内结构复用三段式框架：左侧业务列表、中央任务区、右侧按需详情。左右栏折叠状态为页面局部状态；风险、患者对象和详情选项使用页面局部 computed，不写入全局 store。

### 3.3 业务页面

- `DoctorWorkbench.vue`：医生候选方案、风险、证据、决策和草稿链路。
- `PharmacistReviews.vue`：科室待审医嘱、长期医嘱每日复审、单医嘱/联合用药异常。
- `PatientOverview.vue` 与 `MedicationTimeline.vue`：患者详情和完整治疗周期，供点评、药历、教育复用入口。
- `ResearchWorkbench.vue`：科研队列、点评抽样、变量、质量、统计和报告。
- `KnowledgeReviews.vue`、`RuleGovernance.vue`、`EvidenceCenter.vue`：知识生命周期和证据状态。
- 通过现有路由新增或重命名入口时，不删除后端已有 API 页面，保持能从统一壳访问。

## 4. 跨模块数据流

```text
角色范围
  -> 患者/医嘱/任务列表
  -> 当前主任务
  -> 右侧患者/药品/规则/证据详情
  -> 审核/决策/点评/药历/教育结果
  -> 结局与干预记录
  -> 脱敏科研队列
  -> 固定统计与报告
  -> 知识审核候选
```

页面不自行拼造后端事实。所有事实、风险、审核状态和来源字段来自 `coreApi` 类型或 `flowScenario` 类型；页面只负责分组、排序、折叠和展示。

## 5. 真实数据与验证数据

- 正式模式：通过 `dataAccess`/`coreApi` 读取 Core API；接口失败显示错误并保留可用的确定性安全状态。
- 预览模式：通过版本化 JSON 场景导入，用于浏览器验收，页面显式标注合成验证数据。
- 不新增写死在页面组件中的患者、医嘱或医学规则。
- 新增前端数据字段时同步 TypeScript 类型、JSON Schema、接口 MD 和测试场景。

## 6. 关键安全边界

- 过敏、禁忌、重复、相互作用和剂量状态只显示后端/固定规则结果，前端不自行判定。
- 硬阻断状态始终在中央或顶部风险条可见，折叠不能关闭，也不能被超级管理员绕过。
- 推荐、处方草稿和正式医嘱使用不同标签和操作文案。
- 未发布知识、演示证据和科研草稿不能显示成正式依据。
- 所有前端操作按钮根据权限和状态 computed 禁用，不能通过角色切换伪造审核人。

## 7. 接口契约文档

新增 `docs/10_FRONTEND_BACKEND_API_CONTRACT.md`，以页面任务为索引描述：接口目的、调用角色、请求参数、响应字段、状态变化、错误、权限、审计和前端消费页面。已存在的 OpenAPI 作为接口事实来源，本 MD 不替代 OpenAPI，而是为后端开发提供面向页面的数据和交互说明。

## 8. 兼容性与回滚

- 先改应用壳和页面展示层，再接已有真实 API；避免一次改动后端状态机。
- 每个模块保持旧路由可访问，页面无数据时显示明确空状态。
- 若新页面出现接口字段不一致，保留原始页面消费路径和错误提示，不在 UI 层静默转换成正常值。
