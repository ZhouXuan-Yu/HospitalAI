# HospitalAI 医疗药学工作台前端重塑 PRD

文档版本：V1.0
文档状态：待产品、临床、药学、科研与信息科联合评审
更新时间：2026-08-10
适用范围：桌面端 Web，目标视口 1366×768 与 1920×1080
本轮边界：产品与 UI/UX 需求冻结，不包含代码实现方案

## 1. 产品结论

HospitalAI 前端应从“信息全部铺开的一张综合页面”重塑为“按角色进入、按任务聚焦、按需展开”的医疗药学工作台。

统一界面采用：

```text
顶部横向功能导航
  + 左侧科室/患者/医嘱任务列表
  + 中央当前任务主工作区
  + 右侧按需展开详情区
  + 底部固定操作区（仅在需要决策时出现）
```

医生登录后以处方推荐为核心，只看到本人有权限科室内的患者；药师登录后以当日待审核医嘱为核心，只看到本人负责科室的审方、点评、药历、教育和知识维护功能。低关注度信息默认折叠，点击患者、医嘱、药品、风险或证据后在右侧展开详情，避免主工作区持续拥挤。

## 2. 背景与问题

### 2.1 当前问题

1. 患者事实、药品候选、风险、证据、流程说明和操作按钮同时展示，缺少明确的第一视觉焦点。
2. 推荐方案卡片承载字段过多，医生难以快速判断“能否用、为什么、还缺什么、下一步做什么”。
3. 医生与药师共用接近相同的页面结构，角色职责和待办优先级不突出。
4. 左右区域长时间占据页面宽度，即使用户当前并不需要其中信息。
5. 处方推荐、处方审核、处方点评、药历、用药教育、知识库和科研数据沉淀之间缺少统一入口与状态衔接。
6. 部分信息以技术过程为中心，而不是以临床任务和药学任务为中心。
7. 缺少长期医嘱每日复核、单医嘱与联合用药双层审核、完整治疗周期点评等关键工作模式。

### 2.2 改造前后对比

| 维度 | 改造前 | 改造后 |
|---|---|---|
| 导航 | 左侧大量功能长期占宽 | 顶部横向模块导航，按角色过滤 |
| 左侧区域 | 患者信息与系统导航混合 | 专用于科室、患者或医嘱任务列表 |
| 主工作区 | 多类信息同时铺开 | 只展示当前任务和核心判断信息 |
| 详情 | 在主区域内持续堆叠 | 点击条目后在右侧推挤式展开 |
| 医生视图 | 与药师功能混合 | 聚焦患者和处方推荐 |
| 药师视图 | 风险、任务、证据分散 | 聚焦当日审方队列和异常处理 |
| 推荐卡片 | 完整字段全部展示 | 摘要卡 + 右侧完整详情 |
| 安全风险 | 容易淹没在信息中 | 硬阻断和严重风险跨折叠状态常驻 |
| 模块衔接 | 页面相互独立 | 审方、点评、药历、教育、知识和科研互相跳转并保留上下文 |

## 3. 产品目标与非目标

### 3.1 产品目标

1. 医生在进入页面后 10 秒内识别当前患者、推荐方案、最高风险和是否可生成草稿。
2. 药师在进入页面后 10 秒内识别负责科室的当日待审数量、最高风险任务和长期医嘱复审任务。
3. 用户可在不离开当前任务的情况下查看患者、药品、规则、证据和历史记录详情。
4. 五个核心业务模块共享患者、医嘱、风险、处理结果和审计上下文。
5. 页面只展示当前角色有权访问的数据和操作。
6. 在降低信息密度的同时，不降低医疗安全信息的可见性。

### 3.2 非目标

- 不由 AI 自动诊断。
- 不由 AI 自动开具正式医嘱。
- 不允许大模型自由生成确定性剂量和频次上限。
- 不允许前端角色切换绕过正式权限。
- 不把一次医生采纳或一次药师审核自动升级为正式规则。
- 不把随机抽样、单一 P 值或未经调整的观察性比例直接解释为临床因果结论。
- 本 PRD 不定义后端接口、数据库表、组件代码或技术框架改造方式。

## 4. 目标用户与职责

| 角色 | 主要目标 | 默认入口 | 核心关注 | 允许的主要操作 |
|---|---|---|---|---|
| 医生 | 为本人负责患者完成用药方案判断 | 处方推荐 | 诊断、适用性、硬阻断、主要差异、监测 | 确认、修改、驳回推荐，生成处方草稿 |
| 审方药师 | 完成负责科室当日医嘱审核 | 处方审核 | 单医嘱合理性、联合用药、冲突、重复、剂量状态 | 审核通过、退回、要求补充、记录意见 |
| 点评药师 | 对完整治疗周期进行回顾性评价 | 处方点评 | 全周期用药、问题分类、干预结果、改进建议 | 抽样、点评、复核、形成反馈 |
| 临床药师 | 为重点患者建立和维护药历 | 药历 | 病史、方案变化、临床采集、药学分析 | 选择重点患者、补录、审核、归档 |
| 教育药师 | 形成患者可理解的用药教育材料 | 用药教育 | 适用人群、用法提醒、风险和随访 | 生成草稿、编辑、审核、交付 |
| 知识管理员 | 维护审核规则和药学知识 | 知识库 | 来源、版本、适用范围、审核状态 | 新建、复核、发布、撤回 |
| 科研人员 | 使用脱敏数据完成可复现分析 | 数据分析 | 队列、变量、质量、统计、报告 | 构建队列、冻结、分析、生成报告 |
| 科室/药学管理者 | 查看任务完成与质量改进 | 管理视图 | 积压、时效、问题分布、整改结果 | 查看统计、配置范围、导出审核结果 |

## 5. 权限与数据范围

### 5.1 医生

- 仅展示本人负责科室、医疗组或授权会诊范围内的患者。
- 患者列表不得默认展示其他科室无业务关系患者。
- 可查看当前患者的跨科室安全摘要，但不等于获得其他科室完整病历权限。
- 只能对本人有处方权限的患者执行确认、修改或驳回。

### 5.2 药师

- 仅展示本人负责科室、病区或药学任务组的待审医嘱。
- 处方审核默认展示当日未完成任务及需要每日复审的持续用药医嘱。
- 点评、药历、教育和知识库权限独立配置，不因拥有审方权限自动获得全部功能。

### 5.3 管理与安全要求

- 角色差异由登录身份和权限决定，不把前端角色切换作为正式授权依据。
- 无权限模块不出现在横向导航中。
- 只读权限不显示可执行按钮。
- 超级管理员可以查看调试信息，但不能绕过医疗硬阻断、伪造审核人或删除审计记录。

## 6. 全局信息架构

### 6.1 横向导航

顶部第一行固定展示品牌、当前角色、全局检索、消息和账户信息。第二行展示当前角色可用的业务模块。

**医生导航**

```text
处方推荐 | 我的患者 | 用药追踪
```

**药师导航**

```text
处方审核 | 处方点评 | 药历 | 用药教育 | 知识库 | 数据分析
```

管理者可增加“任务管理”“质量监测”等入口。未授权模块不占位。

### 6.2 业务页面布局

```text
┌─────────────────────────────────────────────────────────────────┐
│ 品牌 / 角色 / 全局搜索 / 消息 / 账户                            │
├─────────────────────────────────────────────────────────────────┤
│ 横向模块导航                                                    │
├──────────────┬───────────────────────────────┬──────────────────┤
│ 左侧业务列表 │ 中央当前任务主工作区            │ 右侧按需详情     │
│ 科室/患者/   │ 推荐、审核、点评、药历或教育    │ 患者/药品/风险/ │
│ 医嘱/任务    │                               │ 证据/审计       │
├──────────────┴───────────────────────────────┴──────────────────┤
│ 当前任务操作栏（仅决策场景出现）                                │
└─────────────────────────────────────────────────────────────────┘
```

### 6.3 折叠原则

- 左侧业务列表可收纳为 52–56px 窄轨，保留列表入口、当前对象头像和待办数量。
- 右侧详情默认关闭，点击患者、医嘱、药品、风险、规则或证据后展开。
- 右侧采用无模态推挤式面板，不覆盖中央任务，不使用阻断式遮罩。
- 1920 宽度允许左右区域同时展开；1366 宽度默认只展开一侧。
- 折叠只改变信息呈现，不改变医疗风险状态。
- 硬阻断、严重过敏、严重 ADR 和关键缺失必须在主工作区保持可见。

### 6.4 详情打开规则

| 点击对象 | 右侧默认打开内容 |
|---|---|
| 患者姓名/头像 | 患者详情与跨就诊安全摘要 |
| 药品名称 | 药品目录信息、适应症、规则与来源 |
| 风险标签 | 命中事实、规则依据、处理要求 |
| 证据状态 | 来源、版本、生效时间、审核状态、原文定位 |
| 修改差异 | 修改前后字段和新增风险 |
| 状态时间 | 完整流程与审计记录 |

面板支持关闭按钮和 Esc。切换详情时保留主工作区选择、筛选和滚动位置。

## 7. 全局视觉与交互规范

### 7.1 视觉方向

- 冷灰白背景、深灰正文、低饱和医疗青绿色主色。
- 琥珀色仅用于强提醒，红色仅用于硬阻断和高危异常。
- 不使用装饰性渐变、插画、大面积彩色卡片或卡片嵌套。
- 通过留白、字号和内容顺序建立层级，减少分割线。
- 卡片圆角不超过 8px。

### 7.2 字体与密度

| 层级 | 建议字号 |
|---|---:|
| 页面标题 | 18–20px |
| 区域标题 | 15–16px |
| 核心任务信息 | 14px |
| 正文与表格 | 13–14px |
| 来源、版本、时间 | 不低于 12px |

正文行高 1.45–1.6。任何重要医疗信息不得依赖悬停才能看到。

### 7.3 状态表达

风险和状态必须同时使用图标、文字和颜色：

- 硬阻断：红色盾牌 + “硬阻断”文字。
- 强提醒：琥珀色警告 + “需药师/医生处理”。
- 一般提示：蓝灰色信息标识。
- 已通过：绿色勾选 + 审核角色和时间。
- 未知：灰色问号 + “未知/待补充”，不得显示为正常。

## 8. 模块一：处方推荐（医生）

### 8.1 目标

帮助医生在当前患者上下文中快速核对系统生成的候选方案，完成确认、修改或驳回，并在安全规则允许时生成处方草稿。

### 8.2 左侧患者列表

默认展示本人负责科室约 10–20 名当前患者，支持科室、病区、医疗组和风险筛选。

每行只展示：

- 床号/患者脱敏姓名
- 年龄、性别
- 当前主要诊断
- 初步推荐方案摘要
- 最高风险等级
- 当前状态：待查看、待决策、已处理、需补充

列表不得直接展示完整药品说明、全部检验或长篇推荐理由。

### 8.3 中央主工作区

第一屏只展示：

1. 当前患者和当前就诊摘要。
2. 无硬阻断/存在硬阻断、强提醒数量、关键缺失数量。
3. 两至三个候选方案摘要。
4. 当前允许执行的医生操作。

候选摘要字段：

- 方案名称与药品组合
- 适用性一句话摘要
- 风险最高等级
- 与其他方案的主要差异
- 最多三个关键监测项
- 证据审核状态
- 是否允许生成草稿

### 8.4 推荐与阈值状态

系统根据预设参数、患者事实、确定性规则和受控证据形成候选。前端需表达以下状态，而不是只显示“推荐成功”：

- 数据完整，可以比较候选。
- 达到医院配置的推荐门槛，等待医生确认。
- 未达到门槛，仅展示风险和缺失信息，不给出优先候选。
- 存在硬阻断，候选仅供查看，不允许提交草稿。
- 证据不足，不补写推荐理由。
- AI 解释服务降级，仍保留患者事实和硬规则结果。

### 8.5 医生操作

- 确认当前推荐并生成“处方草稿”。
- 修改药品方案并查看修改差异。
- 驳回推荐并填写原因。
- 查看药品详情。
- 查看患者详情。
- 切换推荐列表与方案对比。

确认按钮必须显示“生成草稿”，不得使用“开立正式医嘱”。

### 8.6 方案对比

医生主动选择二至三个候选后进入对比模式。固定比较维度包括：

- 适用性
- 硬阻断和强提醒
- 用法用量规则状态
- 主要差异
- 监测要求
- 证据状态

长内容不进入表格单元格，点击后在右侧详情区展开。

### 8.7 验收标准

- [ ] 医生只看到授权范围内患者。
- [ ] 左侧可同时稳定展示至少 10 名患者而不出现过高行高。
- [ ] 进入患者后第一屏可见方案、最高风险、关键缺失和主操作。
- [ ] 点击患者、药品、风险、证据可在右侧查看详情。
- [ ] 硬阻断存在时确认和生成草稿不可用。
- [ ] 未知检验不得展示为正常。
- [ ] 推荐、草稿和正式医嘱状态清楚区分。

## 9. 模块二：处方审核（药师）

### 9.1 目标

以科室为单位，让药师高效完成当日未审核医嘱的单医嘱和联合用药审查，并持续复核未停用长期医嘱。

处方审核需综合患者检查、检验、现病史、既往史、用药史和过敏史等信息；医院可依据本机构规范、指南和药事管理要求建立审核依据。[国家卫生健康委员会《医疗机构处方审核规范》](https://www.nhc.gov.cn/yzygj/c100068/201807/03df2450431348e18feb3701c199262d.shtml)

### 9.2 左侧科室与待审列表

左侧第一层为药师负责科室，展示：

- 科室名称
- 当日未审核数量
- 硬阻断数量
- 超时数量
- 长期医嘱复审数量

选择科室后显示该科室全部待审任务。每行展示：

- 患者脱敏信息与床号
- 医嘱药品和给药途径
- 开始时间、计划结束时间
- 临时/长期医嘱
- 单医嘱风险
- 联合用药风险
- 当前审核状态

### 9.3 每日长期医嘱规则

- 有开始时间、结束时间且仍有效的长期医嘱，在医院规定的每日复核时间窗内重新进入待审核列表。
- 没有停止时间但仍处于有效状态的长期医嘱，每日显示为待复审。
- 已停用、已结束或已撤销医嘱不进入新的每日待审任务，但保留历史审核记录。
- 页面需区分“首次审核”和“持续用药每日复审”。

### 9.4 双层审核视图

**单医嘱合理性**

- 适应症与禁忌症
- 过敏和严重 ADR
- 药品目录状态
- 给药途径
- 用法用量规则状态
- 特殊人群和关键检验

**联合用药合理性（当天有效用药范围）**

- 重复药品
- 重复药理类别
- 配伍禁忌
- 药物相互作用
- 跨科室当前有效用药冲突
- 医院规则定义的补充用药或伴随用药缺失提示

“补充用药”只作为医院审核规则的命中结果展示，不由 AI 自由推断。

### 9.5 异常提示

异常标签需显示：

- 风险等级
- 异常类型
- 命中药品
- 命中患者事实
- 规则来源和版本
- 建议处理动作
- 是否阻断审核通过

点击异常后在右侧展开完整规则和证据。未发布知识不得作为正式审核依据。

### 9.6 药师操作

- 一键审核当前无异常任务。
- 批量审核筛选范围内的低风险任务。
- 退回医生并填写原因。
- 要求补充信息。
- 记录线下沟通结果。
- 双击任务进入患者完整详情，同时必须提供可见的“查看患者详情”按钮，避免操作只依赖双击。

批量审核不得包含：硬阻断、未处理强提醒、关键数据缺失、规则版本过期或审核上下文失效的医嘱。

### 9.7 验收标准

- [ ] 药师只看到本人负责科室的任务。
- [ ] 当日未审核医嘱与长期医嘱每日复审可区分。
- [ ] 单医嘱和联合用药风险分别展示。
- [ ] 同日不同医嘱之间的重复和相互作用可被聚合显示。
- [ ] 一键审核自动排除存在阻断或未处理风险的任务。
- [ ] 双击和显式按钮都能进入患者详情。
- [ ] 所有审核动作保留操作人、时间、意见和规则版本。

## 10. 模块三：处方点评（回顾性分析）

### 10.1 目标

面向药师完成单个患者完整治疗周期及科室/药品专题的回顾性用药评价，发现问题并形成改进闭环。

处方点评应评价处方规范性和药物临床使用适宜性，包括适应证、药物选择、给药途径、用法用量、相互作用和配伍禁忌等。[国家卫生健康委员会《医院处方点评管理规范（试行）》](https://www.nhc.gov.cn/wjw/c100175/201003/62c5a322a2204f1c9096e1afa0471489.shtml)

### 10.2 分析对象

- 单个患者从入院到出院/疗程结束的全部用药。
- 包括口服、注射、输液、外用及其他给药途径。
- 包括开始、调整、停用、换药和重新启用事件。
- 同时展示诊断、检验、治疗反应、不良事件和干预结果的时间关系。

### 10.3 页面结构

左侧为点评任务和抽样队列，中间为治疗周期时间线与问题列表，右侧为当前药品、规则、证据和历史处置详情。

默认展示：

- 患者基本情况
- 治疗周期
- 用药品种数
- 给药途径分布
- 问题数量及分类
- 当前点评状态

### 10.4 点评任务类型

- 全量点评
- 随机抽样点评
- 分层随机抽样点评
- 指定科室
- 指定药品/药品类别
- 指定疾病
- 指定问题类型

随机抽样必须保留抽样总体、条件、抽样方法、抽样比例、随机种子、执行时间和执行人，保证可复核。

### 10.5 点评结果

- 合理
- 不规范
- 用药不适宜
- 超常用药
- 待专家复核

每个结论需绑定事实、规则、证据、药师意见和复核状态。系统可生成点评草稿，但不能自动形成正式点评结论。

### 10.6 验收标准

- [ ] 可查看患者完整治疗周期的所有用药事件。
- [ ] 可按给药途径、时间和问题类型筛选。
- [ ] 随机抽样过程可追溯和复现。
- [ ] 点评问题可以回链到具体患者事实和医嘱。
- [ ] 正式结论必须由有权限药师确认。
- [ ] 点评结果可形成科室改进任务，但不会自动发布为知识规则。

## 11. 模块四：药历

### 11.1 目标

为重点和重症患者建立由临床药师主导的精细化用药记录，减少重复抄录，把药师时间集中在临床采集、方案分析和药学干预上。

### 11.2 触发方式

- 药师主动从患者列表选择“纳入重点患者”。
- 可由高风险、重症、复杂联合用药等条件提示候选，但不得自动创建正式药历。
- 选中后建立药历草稿和责任药师。

### 11.3 内容结构

**首页**

- 患者基础信息
- 主诉、现病史、既往史
- 家族史、过敏史、不良反应史
- 当前诊断和合并症

**用药方案**

- 药品名称、给药途径、用法和规则状态
- 开始、调整、停用时间
- 当前和历史方案

**方案调整分析**

- 调整前后差异
- 调整原因
- 患者反应
- 药学分析
- 干预建议及采纳结果

### 11.4 自动导入与手工补充

| 数据类型 | 默认来源 |
|---|---|
| 基础信息、诊断、检验、用药记录、药品名称 | 系统自动导入，只读引用 |
| 患者口述、依从性、家庭用药、现场观察 | 药师手工补充 |
| 调整原因、药学判断、干预分析 | 药师撰写并签名 |

自动导入内容必须显示来源和采集时间；药师补充内容必须显示作者和更新时间。手工内容不得覆盖原始事实。

### 11.5 月度任务与收费

- “每名药师每月 2 份药历”作为医院可配置任务指标，默认值可设为 2，但不得写死为全国统一要求。
- 页面展示个人目标、已完成、审核中和逾期数量。
- 药历收费作为医院配置项，仅展示收费项目状态、计费条件和结算结果。
- 未完成医院审批、物价和收费配置时，不允许自动计费。

### 11.6 验收标准

- [ ] 药师可主动选择重点患者并建立药历草稿。
- [ ] 自动导入与手工录入内容视觉上明确区分。
- [ ] 支持保存草稿、提交审核、退回修改和归档。
- [ ] 药历内容可回链到原始患者事实和医嘱。
- [ ] 月度数量目标可以由医院配置。
- [ ] 收费状态不等于自动完成计费。

## 12. 模块五：用药教育

### 12.1 定位

用药教育是独立业务模块，不作为药历的附属页。它面向患者或照护者提供经审核、可理解、可追踪的用药指导。

### 12.2 第一阶段范围

- 从患者或药品入口建立教育任务。
- 自动带入药品名称和已确认方案。
- 选择医院已审核教育模板。
- 药师编辑患者化说明。
- 记录教育对象、方式、时间和确认结果。
- 输出可打印或可发送的教育材料草稿。

### 12.3 内容结构

- 药品用途
- 如何使用
- 重要注意事项
- 常见不良反应和就医提示
- 漏服/误服处理入口
- 饮食、生活和随访提醒
- 患者理解确认

涉及具体剂量、停药和紧急处置时，只能引用已确认医嘱和已发布模板，不允许 AI 自由补写。

### 12.4 待确认事项

- 教育材料交付渠道。
- 患者签收和理解确认形式。
- 多语言、适老化和无障碍要求。
- 是否与门诊、住院和出院流程分别配置模板。

### 12.5 验收标准

- [ ] 用药教育拥有独立导航和任务列表。
- [ ] 可从处方审核、药历和患者详情跳转并保留患者上下文。
- [ ] 未审核模板不得用于正式交付。
- [ ] 教育内容清楚区分系统带入、模板内容和药师编辑内容。
- [ ] 第一阶段对尚未确认的交付渠道使用明确占位状态。

## 13. 用药知识库

### 13.1 目标

由药师维护可审核、可版本化、可撤回的院内用药知识，为处方推荐、审核、点评、药历和教育提供受控依据。

### 13.2 知识类型

- 指南要求
- 科室规范
- DRG/DIP 管理要求
- 药品说明书
- 配伍禁忌
- 药物相互作用
- 禁忌症和特殊人群规则
- 重复用药和重复药理类别规则
- 医院定义的补充/伴随用药规则
- 用药教育模板

### 13.3 生命周期

```text
草稿 → 待复核 → 已发布 → 已撤回/已过期
```

每条知识必须展示：

- 来源名称和原文定位
- 版本、生效时间和失效时间
- 适用科室、疾病、人群和药品范围
- 规则等级
- 维护人、复核人和发布时间
- 当前审核状态

未审核或已撤回内容不得参与正式推荐和审核。

### 13.4 知识冲突

同一药品或规则存在多个版本时，前端需提示：

- 冲突来源
- 权威层级
- 生效范围
- 当前推荐链路实际采用版本
- 待处理责任人

### 13.5 验收标准

- [ ] 药师可按类型、药品、科室、状态和生效时间检索知识。
- [ ] 发布与撤回状态在调用页面同步可见。
- [ ] 每个异常提示可追溯到具体知识版本。
- [ ] 未审核知识不会显示为正式依据。
- [ ] 知识变更不自动覆盖历史审核记录。

## 14. 数据沉淀与方案分析

### 14.1 数据沉淀目标

持续沉淀患者用药暴露、方案调整、治疗反应、不良事件、随访、医生决策和药师干预数据，为质量改进、科研分析和模型评估提供基础。

### 14.2 前端需表达的数据状态

- 数据来源
- 采集时间
- 当前版本
- 缺失状态
- 审核状态
- 是否脱敏
- 是否纳入科研队列
- 是否存在后续更新

### 14.3 方案效果对比

支持按疾病、人群、药品方案、科室和时间窗构建分析队列，比较不同方案下的：

- 治疗反应
- 不良事件
- 住院结局
- 再入院或随访结果
- 方案调整和停药原因

结果页必须同时展示样本量、缺失情况、基线差异和适用范围。

### 14.4 抽样与统计要求

- 支持全量、简单随机、分层随机和按条件抽样。
- 抽样方法、总体、比例、随机种子和纳排过程必须保存。
- 统计计划在运行前锁定，结果由固定统计程序产生。
- 可以展示精确 P 值，并将 `P < 0.05` 作为预先设定的统计阈值之一。
- 不允许仅根据是否小于 0.05 自动生成“有效/无效”或“更适合”的临床结论。
- 同时展示效应量、置信区间、样本量、缺失、混杂、敏感性分析和多重比较处理。
- 观察性研究报告应覆盖标题、摘要、方法、结果、讨论等 STROBE 关键项。[STROBE Statement](https://www.strobe-statement.org/)

### 14.5 医学结论分级

| 层级 | 页面允许表达 |
|---|---|
| 描述性结果 | “队列中方案 A 改善比例为…” |
| 统计关联 | “调整后模型显示关联，效应量与区间为…” |
| 假设生成 | “该信号值得在更大样本中验证” |
| 临床适用性结论 | 必须经过预注册、充分样本、混杂控制、外部验证和多角色审核 |

系统不得将前三类自动升级为“某药更适合某类患者”。

### 14.6 科研交付物

冻结研究后需提供：

- 去标识数据包 ZIP
- 变量字典
- 纳排日志
- 数据质量报告
- 固定统计结果
- 脚本版本与输入/输出哈希
- 专业医学数据结论报告
- 审核记录与数据可用性说明

### 14.7 机器学习应用边界

- 研究数据可作为模型训练候选数据，但进入训练前必须完成脱敏、授权、质量检查和版本冻结。
- 训练集、验证集和测试集必须区分。
- 模型性能、分层表现、漂移和偏倚需独立评估。
- 新模型不得直接替换临床推荐逻辑。
- 上线前必须完成临床、药学、安全和管理审核。

### 14.8 验收标准

- [ ] 可按疾病、人群、药品方案、科室和时间构建分析队列。
- [ ] 抽样过程可复现。
- [ ] 结果同时展示效应量、置信区间和精确 P 值。
- [ ] 页面不以 `P < 0.05` 自动生成临床优越性结论。
- [ ] 上游数据变化后，冻结数据集、统计结果和报告被标记失效。
- [ ] 科研数据和合成演示数据明确区分。
- [ ] 未审核科研结论不得进入正式知识库或处方推荐。

## 15. 跨模块业务闭环

### 15.1 医生到药师

```text
患者进入医生列表
→ 处方推荐
→ 医生确认/修改/驳回
→ 处方草稿
→ 正式系统形成待审医嘱
→ 药师单医嘱与联合用药审核
→ 审核结果回到医生任务
```

### 15.2 审方到点评

```text
每日审方记录
→ 用药执行与调整
→ 治疗周期结束
→ 进入处方点评总体
→ 全量或抽样点评
→ 科室改进任务
```

### 15.3 重点患者药学服务

```text
高风险/重点患者提示
→ 药师主动纳入药历
→ 自动导入患者事实
→ 临床采集与手工分析
→ 药历审核归档
→ 形成用药教育任务
```

### 15.4 知识与科研

```text
审核、点评、药历和结局数据沉淀
→ 脱敏科研队列
→ 固定统计与报告审核
→ 知识候选
→ 多角色审核发布
→ 后续规则/推荐链路引用
```

科研结论不能跳过知识审核直接进入处方推荐。

## 17. 异常与空状态

| 场景 | 页面要求 |
|---|---|
| 无权限 | 不展示模块或显示只读原因，不提供操作入口 |
| 当前无患者/无待办 | 展示明确空状态和筛选范围 |
| 患者事实加载失败 | 保留已加载内容，标记失败来源和重试入口 |
| 关键检验缺失 | 显示未知和缺失来源，不按正常处理 |
| 知识库不可用 | 硬规则继续工作，证据和解释显示降级 |
| 推荐未达阈值 | 展示缺失与风险，不伪造候选 |
| 数据版本过期 | 禁止继续决策，要求刷新上下文 |
| 长期医嘱已停用 | 从当前待审移除，历史审核可回查 |
| 批量审核包含高风险 | 自动剔除并说明原因 |
| 科研样本不足 | 展示无法形成稳定结论，不隐藏小样本问题 |

## 18. 可用性与无障碍

- 1366×768 和 1920×1080 下无页面级横向滚动、文字重叠和按钮溢出。
- 关键任务支持键盘访问和清晰焦点状态。
- 双击不能作为唯一入口。
- 风险不能只依赖颜色表达。
- 折叠标题需显示内容类型、风险数量和当前状态。
- 右侧详情关闭后保留当前对象、筛选和滚动位置。
- 列表刷新不得改变用户当前选择，除非任务已失效。

## 19. 产品指标

### 19.1 效率指标

- 医生打开患者到完成推荐处理的中位时长。
- 药师单医嘱审核中位时长。
- 当日待审任务按时完成率。
- 需要展开患者详情的任务比例。
- 药历自动带入字段比例和人工整理耗时。

### 19.2 质量指标

- 硬阻断绕过次数必须为 0。
- 关键缺失误显示为正常次数必须为 0。
- 批量审核误包含未处理高风险任务次数必须为 0。
- 未审核知识进入正式推荐次数必须为 0。
- 点评结论、药历和科研报告的来源可追溯率达到 100%。

指标用于产品和流程质量改进，不直接等同于临床疗效结论。

## 22. 全局验收清单

- [ ] 不同角色登录后横向导航、列表数据和操作按钮符合权限范围。
- [ ] 左侧区域只承担当前模块的科室、患者、医嘱或任务列表。
- [ ] 右侧详情按点击对象展开，不遮挡主工作区。
- [ ] 第一屏只展示当前任务的核心信息。
- [ ] 硬阻断在任何折叠状态下始终可见且不可绕过。
- [ ] 医生处方推荐可完成确认、修改、驳回和草稿状态表达。
- [ ] 药师处方审核支持单医嘱、联合用药和长期医嘱每日复审。
- [ ] 处方点评覆盖患者完整治疗周期和全部给药途径。
- [ ] 药历区分自动导入事实与药师手工分析。
- [ ] 用药教育为独立模块且只使用已审核内容正式交付。

- [ ] 统计结果不把单一 P 值解释为临床优越性。
- [ ] 科研与机器学习数据均具备脱敏、版本、质量和审核状态。

## 23. 待医院确认

1. 医生负责患者范围按科室、医疗组、床位还是会诊关系确定。
2. 药师负责范围按科室、病区、药学组还是班次确定。
3. 长期医嘱每日复审的时间窗、例外条件和超时规则。
4. “补充用药”规则的正式定义和依据来源。
5. 一键审核允许覆盖的风险等级和任务类型。
6. 点评抽样比例、周期、专项点评范围和复核角色。
7. 药历月度目标、审核流程和收费政策。
8. 用药教育交付渠道、签收方式和模板范围。
9. DRG/DIP 规则在推荐、审核和管理提示中的使用边界。
10. 科研数据使用授权、伦理流程、分析方法和模型训练准入要求。
