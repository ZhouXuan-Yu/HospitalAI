# 企业级医学科研工作台纵向链路 PRD

## 目标

为医院药师交付可审计、可复现、可审核的回顾性药物比较研究流程：

`选题立项 -> Excel 数据导入 -> 队列与变量定义 -> 数据质控与冻结 -> 统计分析 -> 报告审核 -> 数据与证据包导出`

首条纵向切片固定为“65 岁及以上非瓣膜性房颤患者中阿哌沙班与利伐沙班的有效性和安全性比较”。系统输出供论文写作使用的数据分析材料和待审核报告，不自动形成临床结论；合成数据不得作为科研证据。

## 用户与权限

| 角色 | 职责 | 边界 |
|---|---|---|
| 药师/项目负责人 | 建立选题、导入数据、定义队列与变量、发起分析、初审报告 | 不批准统计方法或最终发布 |
| 统计师 | 审核统计分析计划、模型诊断和结果 | 不代替医学负责人批准医学结论 |
| 医学负责人 | 审核临床解释、局限性和最终成果包 | 不修改原始数据或统计结果 |
| 管理员 | 维护模板、角色、数据源和运行配置 | 不绕过审核、不删除审计 |

## 首期研究方案

- 设计：新使用者回顾性队列。
- 人群：年龄 >= 65 岁、非瓣膜性房颤、满足洗脱期和最短随访要求。
- 暴露与对照：阿哌沙班 vs 利伐沙班。
- 主要有效性结局：缺血性卒中或系统性栓塞。
- 主要安全性结局：大出血。
- 次要结局：全因死亡、再入院、换药或停药。
- 首期数据：固定随机种子生成约 2,000 例明确标注的合成 Excel，经与未来真实数据相同的导入、校验、标准化和分析链路处理。
- 后续数据：通过适配器接入 HIS/EMR/LIS/PACS；首期不连接真实医院系统、不处理真实身份信息。

## 五个核心模块

### 1. 选题管理

输入研究模板、PICO、结局、周期、伦理或豁免编号和负责人；检查临床价值、数据可得性、样本量可行性和结局可定义性；输出版本化协议、审核状态及所需字段清单。

### 2. 数据提取

上传版本化 `.xlsx`，记录数据源和合成/真实标识。系统校验文件哈希、模板、类型、代码、日期、重复、异常、缺失和纳排前置条件；错误按行列返回且不部分发布。输出导入批次、来源血缘、标准化研究记录、错误报告和候选数据集版本。

### 3. 算法分析

冻结前生成纳排流程、缺失率、分布、异常值、重复和逻辑一致性报告。冻结后按审核的统计计划执行描述统计、SMD、倾向评分与 IPTW、Kaplan-Meier、log-rank、Cox 回归、比例风险假设检查、亚组和敏感性分析。所有数值由固定 Python 程序计算，并记录代码、环境、参数和结果哈希。

### 4. 报告生成

根据协议、数据质量和结构化统计结果生成待审核报告，依次经过药师、统计师、医学负责人审核。报告包含背景、方法、结果、图表、讨论、局限性、结论、伦理、可复现性和审核记录；终审前不得标记为可发布。

### 5. 数据导出

终审后执行去标识化和敏感字段扫描，导出 ZIP：清洗数据 CSV/XLSX、数据字典、纳排日志、质量报告、统计计划、Python 代码、依赖锁、结果、图表、DOCX/PDF/Markdown 报告、审计记录、SHA-256 清单和 README。

1. `docs/api/research/01-topic-management-api.md`
2. `docs/api/research/02-data-import-api.md`
3. `docs/api/research/03-cohort-quality-api.md`
4. `docs/api/research/04-analysis-api.md`

OpenAPI 是机器可读契约的唯一权威；页面文档描述角色、字段、状态、错误码、幂等、审计和联调示例，并与 OpenAPI 保持一致。

## 业务与质量规则

- 前端不写死研究记录；合成数据必须通过正式导入接口进入。
- 原始文件、标准化数据集、冻结快照、分析、报告和成果包均版本化且不可覆盖。
- 未通过质控不得冻结；未冻结不得分析；分析未完成不得生成结果报告；三级审核未完成不得生成发布成果包。
- 上游协议、映射、队列、变量、缺失策略或统计计划变更时，下游成果全部失效。
- 重复上传、冻结、分析和导出请求以幂等键去重。
- 缺失值保留缺失类型和策略，不得当作正常值。
- 纳排、变换、参数、人工修改、状态迁移和下载均写入不可删除审计。
- 合成结果始终显示“仅用于流程验证，不构成医学证据或科研结论”。

## 非功能要求

- Linux x86_64 医院内网部署；无外网和无模型服务时统计主链路可运行。
- 最小权限、上传白名单和限额、公式注入/路径穿越防护、日志脱敏、去标识化和追加式审计。
- 2,000 行 Excel 导入和质控在开发基线环境 60 秒内完成；分析异步执行，可查询、取消和重试。
- 导入发布、冻结、审核使用事务与乐观并发；失败任务不能产生可用成果。
- 研究模板、数据源适配器、字段映射和算法配置版本化。
- 每次运行记录关联 ID、耗时、行数、告警、错误、数据和代码哈希。

## 验收标准

- [ ] 确定性生成约 2,000 例合成 Excel，覆盖正常、缺失、重复、异常日期、极端值和无效编码。
- [ ] Excel 经正式接口导入，数据库可回读批次、来源、标准化记录、错误和哈希。
- [ ] 选题至成果包状态真实衔接，页面刷新后不丢失。
- [ ] 质控展示纳排、缺失、重复、分布和逻辑错误，失败数据不能冻结。
- [ ] Python 完成约定统计流程，同一数据和配置产生相同结果哈希。
- [ ] 报告表格与图形可追溯到统计结果和代码，证据不足时明确标注。
- [ ] 三级审核顺序执行，越权、跳级和伪造审核人被拒绝并审计。
- [ ] ZIP 完整、哈希可复核、无直接身份字段，且合成标识不可移除。
- [ ] 六个页面 API 文档与 OpenAPI 一致并通过契约测试。
- [ ] Java、Python、Vue、Playwright 覆盖正常、异常和边界流程。
- [ ] 提供实际命令、测试数量、API 响应、数据库回读、报告和 ZIP 清单。

## 不在首期范围

真实医院接口、真实患者数据、PACS 影像算法、自由文本 NLP、多中心联邦分析、前瞻性随机分组、自动投稿、自动署名，以及自动生成或发布医学结论。
