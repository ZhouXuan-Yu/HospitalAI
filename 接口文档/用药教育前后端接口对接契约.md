## 1. 目标与业务边界

用药教育模块用于医生或药师根据当前患者的真实用药事实，编写、生成、编辑和审核患者可理解的用药教育内容。教育内容是处方和药师审核的辅助材料，不是正式医嘱，不得直接改变剂量、频次、疗程、停药状态或处方审核结果。

核心闭环：

~~~text
选择有权限的患者和当前就诊
  -> 读取患者安全事实、当前有效用药和缺失信息
  -> 选择医师手写或患者画像辅助模式
  -> 保存画像和教育目标
  -> 生成可编辑教育草稿，或直接保存手写内容
  -> 医生/药师编辑并确认事实
  -> 提交药师审核
  -> 药师通过、退回或要求补充
  -> 审核通过后按医院配置进入发送/打印/患者端渠道
  -> 保存版本、来源、审核、发送回执和审计事件
~~~

### 1.1 明确不在本模块完成的事项

- 不自动诊断疾病，不评价患者是否适合某种治疗方案。
- 不自动开方，不创建正式医嘱，不修改正式医嘱。
- 不让大模型自由生成剂量、频次、疗程、停药条件或最大剂量。
- 不把患者分类画像当作医学事实；画像只影响表达方式、沟通重点和提醒优先级。
- 不把未知或缺失的药品信息补写为正常值。
- 未经药师审核的内容不得发送患者，不得进入正式患者教育档案。
- 前端不能决定患者、操作者、科室权限和安全事实；这些字段必须由后端从认证和统一医疗模型中解析。

### 1.2 页面模式

| 模式 | 前端值 | 用途 | 是否调用模型 |
|---|---|---|---:|
| 医师手写 | manual | 医师直接编写教育内容 | 否 |
| 患者画像辅助 | profile_assisted | 选择患者沟通画像和教育目标，生成可编辑草稿 | 可调用，经统一 AI 网关 |

患者画像不得包含歧视性或未经确认的医学判断。推荐的分类是沟通和执行特征，例如老年/记忆困难、普通成人、专业人士、家属照护、多重用药依从性风险。

## 2. 认证、权限与通用约定

### 2.1 基础请求

~~~http
Authorization: Bearer <OIDC access token>
Content-Type: application/json
Accept: application/json
X-Request-Id: <client-generated-uuid>
Idempotency-Key: <uuid-for-write-request>
If-Match: "<draft-version>"
~~~

- 所有生产接口使用同源 /api，医院网关负责认证和路由。
- 时间使用带时区的 ISO-8601，例如 2026-08-10T09:30:00+08:00。
- 日期使用 YYYY-MM-DD，审核日按医院业务时区计算，默认 Asia/Shanghai。
- 所有写接口必须幂等；保存草稿和审核提交必须校验版本，禁止静默覆盖。
- patientId、encounterId、draftId、reviewId 等 ID 由后端生成或从统一模型读取，前端不能用姓名代替 ID。

### 2.2 权限矩阵

| 操作 | 医生 | 药师 | 研究人员 | 管理员 | 开发环境超级管理员 |
|---|---:|---:|---:|---:|---:|
| 查看本人负责范围患者教育上下文 | 是 | 按授权 | 仅脱敏 | 按授权 | 是 |
| 创建手写教育草稿 | 是 | 是 | 否 | 按授权 | 是 |
| 使用画像辅助生成草稿 | 是 | 是 | 否 | 按授权 | 是 |
| 编辑未审核草稿 | 创建人或被授权协作者 | 是 | 否 | 按授权 | 是 |
| 提交药师审核 | 是 | 是 | 否 | 按授权 | 是 |
| 通过/退回教育内容 | 按医院配置 | 是 | 否 | 按授权 | 不得伪造审核人 |
| 发送患者 | 按医院配置 | 按医院配置 | 否 | 按授权 | 不得绕过审核 |
| 查看审计事件 | 按权限 | 按权限 | 脱敏范围 | 按权限 | 是，不得删除 |

后端必须根据当前令牌重新计算患者和科室范围。不能信任请求体中的 operatorId、role、departmentId、reviewerId 或 patientId 来扩大权限。

### 2.3 通用错误

~~~json
{
  "code": "MEDICATION_EDUCATION_FORBIDDEN",
  "message": "当前用户无权访问该患者的用药教育工作区",
  "traceId": "trace-20260810-000001",
  "requestId": "req-20260810-000001",
  "details": []
}
~~~

| HTTP | code | 前端处理 |
|---:|---|---|
| 400 | INVALID_PARAMETER | 保留页面内容，标记错误字段 |
| 401 | UNAUTHENTICATED | 跳转认证或显示登录失效 |
| 403 | MEDICATION_EDUCATION_FORBIDDEN | 显示无权限，不重试 |
| 404 | EDUCATION_WORKSPACE_NOT_FOUND | 刷新患者列表并提示记录不存在 |
| 409 | EDUCATION_VERSION_CONFLICT | 重新读取草稿，要求用户确认合并 |
| 422 | EDUCATION_FACT_INSUFFICIENT | 显示缺失事实，不允许进入审核或发送 |
| 423 | EDUCATION_REVIEW_REQUIRED | 阻止发送，显示药师审核状态 |
| 429 | RATE_LIMITED | 按 Retry-After 延迟重试 |
| 500 | MEDICATION_EDUCATION_INTERNAL_ERROR | 显示错误和 traceId，不显示成功 |
| 503 | AI_GATEWAY_UNAVAILABLE | 保留患者事实，允许手写模式 |

## 4. 数据模型

### 4.1 基础类型

~~~ts
type ISODate = string
type ISODateTime = string
type UUID = string

type EducationMode = 'manual' | 'profile_assisted'
type DraftStatus =
  | 'draft'
  | 'generating'
  | 'generated'
  | 'needs_review'
  | 'returned'
  | 'approved'
  | 'delivery_pending'
  | 'delivered'
  | 'generation_failed'
  | 'withdrawn'

type ReviewDecision = 'approved' | 'returned' | 'needs_more_information'
type DeliveryChannel = 'patient_app' | 'sms' | 'print' | 'inpatient_message'
type Provider = 'human' | 'deepseek' | 'local_fallback'
~~~

### 4.2 患者教育列表项

### 4.3 事实来源

所有用于教育的关键事实都必须保留来源，不得只返回拼接后的中文展示句。

~~~ts
interface FactRef {
  factId: string
  type: 'diagnosis' | 'medication_order' | 'allergy' | 'adverse_reaction' | 'lab' | 'encounter' | 'other'
  label: string
  value: string
  sourceSystem: 'his' | 'emr' | 'lis' | 'pharmacy' | 'patient_report' | 'approved_knowledge'
  sourceId: string
  collectedAt: ISODateTime
  dataVersion: string
  missingStatus: 'present' | 'missing' | 'unknown' | 'conflicted'
  verified: boolean
}
~~~

### 4.4 当前用药事实

~~~ts
interface EducationMedicationFact {
  orderId: string
  drugCode: string
  genericName: string
  brandName?: string | null
  strength?: string | null
  dosageForm?: string | null
  dose?: number | null
  doseUnit?: string | null
  frequency?: string | null
  route?: string | null
  timing?: string | null
  startAt: ISODateTime
  endAt?: ISODateTime | null
  status: 'active' | 'stopped' | 'cancelled' | 'completed'
  isLongTerm: boolean
  orderDepartment: { departmentId: string; departmentName: string }
  source: FactRef
  dosageVerified: boolean
}
~~~

dosageVerified=false 或任意剂量字段缺失时，生成服务只能输出“用法待医嘱/药师确认”，不能推导数值。

### 4.5 患者沟通画像

~~~ts
interface MedicationEducationProfile {
  category:
    | 'older_low_literacy'
    | 'general_adult'
    | 'professional'
    | 'caregiver'
    | 'polypharmacy'
  literacy: 'general' | 'low' | 'professional'
  communication: 'plain' | 'detailed' | 'technical'
  caregiver: 'self' | 'caregiver' | 'professional'
  adherenceRisk: 'unknown' | 'low' | 'high'
  notes?: string
  source: 'clinician_input'
}
~~~

画像字段必须记录创建人和时间。画像是沟通偏好，不得进入患者诊断、过敏、疗效或风险事实表。

### 5.4 生成画像辅助教育草稿

~~~http
POST /api/pharmacy/medication-education/drafts/EDU-DRAFT-0001/generate
If-Match: "1"
Idempotency-Key: 9b7c5a0e-2b3c-4f0b-9c6d-222222222222
~~~

请求：

~~~json
{
  "goals": ["purpose", "method", "missed_dose", "warning", "monitoring"],
  "regenerate": false
}
~~~

后端处理要求：

1. 重新读取患者事实和 sourceFactSnapshot，不能信任前端提交的事实文本。
2. 校验当前用户权限、草稿版本、当前就诊状态和安全事实。
3. 通过统一 AI Gateway 调用模型；Core API 不把 DeepSeek 密钥返回前端。
4. AI 输入不得包含姓名、身份证号、手机号、住址或原始病案号等直接身份信息。
5. AI 输出必须经过结构化解析、来源绑定、药品白名单校验、数值校验和敏感信息检查。
6. 缺失剂量、频次、疗程时，只能输出“待医嘱/待药师确认”，不能生成数值。
7. 生成失败不得把状态改成 generated，应保存失败原因和重试信息。

建议异步响应：

~~~json
{
  "generationId": "GEN-EDU-0001",
  "draftId": "EDU-DRAFT-0001",
  "status": "generating",
  "draftVersion": 2,
  "provider": "deepseek",
  "deterministic": false,
  "poll": {
    "method": "GET",
    "path": "/api/pharmacy/medication-education/drafts/EDU-DRAFT-0001"
  }
}
~~~

生成完成后的草稿响应至少包含 draftId、status、version、contentText、contentStructured、generation 和 auditEventId。generation 必须记录 provider、model、promptVersion、inputHash、outputHash、deterministic、generatedAt 和 failureCode。

~~~json
    "source": "clinician_input"
  },
  "goals": ["purpose", "method", "warning", "monitoring"]
}
~~~

保存前必须检查 sourceFactIds 属于该患者事实快照、结构化药品来自当前有效医嘱、正文和结构化内容一致、未确认的数值没有被补写。手写模式也必须保留事实快照和操作者，不因 mode=manual 绕过审核。

### 5.6 提交药师审核

~~~http
POST /api/pharmacy/medication-education/drafts/EDU-DRAFT-0001/submit-review
If-Match: "4"
Idempotency-Key: 9b7c5a0e-2b3c-4f0b-9c6d-444444444444
~~~

请求：

~~~json
{
  "submitNote": "已核对当前教育对象和患者沟通画像。",
  "confirmedFactIds": ["FACT-E001-DX-001", "FACT-E001-MED-001"],
  "unresolvedItems": ["剂量和频次待药师确认"]
}
~~~

200 响应：

~~~json
{
  "draftId": "EDU-DRAFT-0001",
  "status": "needs_review",
  "version": 5,
  "reviewId": "EDU-REVIEW-0001",
  "assignedRole": "pharmacist",
  "auditEventId": "AUD-EDU-0003"
}
~~~

若存在 blocking_for_review 缺失项，后端返回 422 EDUCATION_FACT_INSUFFICIENT，允许保存草稿，但不允许提交审核或发送。

### 5.7 药师审核

~~~http
POST /api/pharmacy/medication-education/drafts/EDU-DRAFT-0001/review
If-Match: "5"
Idempotency-Key: 9b7c5a0e-2b3c-4f0b-9c6d-555555555555
~~~

请求：

~~~json
{
  "decision": "approved",
  "note": "已核对当前用药事实；缺失剂量部分保持待确认提示。",
  "checkedFactIds": ["FACT-E001-DX-001", "FACT-E001-MED-001"],
  "riskHandling": "未将未知剂量补写为确定数值，患者端发送前保留药师审核边界。"
}
~~~

允许的状态转移：

~~~text
draft -> generated -> needs_review
draft -> needs_review
generated -> needs_review
needs_review -> approved
needs_review -> returned
needs_review -> needs_more_information
approved -> delivery_pending
delivery_pending -> delivered
~~~

approved 时必须确认草稿版本最新、审核人具有药师权限，并保存审核人、审核时间、意见、事实版本和审计事件。审核不能修改正式医嘱，也不能自动改变处方审核结果。

### 5.8 患者端发送或打印

只有 approved 草稿可以调用：

~~~http
POST /api/pharmacy/medication-education/drafts/EDU-DRAFT-0001/deliveries
~~~

请求：

~~~json
{
  "channel": "patient_app",
  "recipient": {
    "patientId": "P001",
    "contactRef": "PATIENT_APP_ACCOUNT_REF"
  },
  "message": "您的用药教育内容已更新，请以药师审核后的版本为准。"
}
~~~

前端不得传入手机号、身份证号等原始联系信息。后端从患者端账户映射中读取发送目标，并返回脱敏发送状态和回执。

## 6. AI Gateway 后端内部接口

前端不能调用 DeepSeek 官方接口，也不能拿到 DEEPSEEK_API_KEY。Core API 通过内部 AI Gateway 调用：

~~~http
POST /internal/ai/medication-education/generations
~~~

内部请求必须使用脱敏上下文，至少包含年龄、性别、科室、诊断、已验证用药、过敏、不良反应、缺失信息、画像和教育目标；不得包含姓名、身份证号、手机号、住址和原始病案号。

~~~json
{
  "generationId": "GEN-EDU-0001",
  "promptVersion": "medication-education.v1",
  "modelPolicy": {
    "provider": "deepseek",
    "model": "deepseek-chat",
    "temperature": 0.2
  },
  "deidentifiedContext": {
    "age": 66,
    "sex": "female",
    "department": "呼吸内科",
    "diagnosis": "社区获得性肺炎",
    "medications": [
      {
        "drugCode": "NS-09",
        "name": "0.9%氯化钠注射液",
        "verifiedRegimen": null,
        "route": "静脉滴注"
      }
    ],
    "allergies": [],
    "adverseReactions": [],
    "missingInfo": ["剂量和频次"],
    "profile": {
      "category": "older_low_literacy",
      "communication": "plain",
      "caregiver": "caregiver",
      "adherenceRisk": "high",
      "goals": ["purpose", "method", "warning", "monitoring"]
    }
  }
}
~~~

AI Gateway 响应必须带 generationId、provider、model、content、inputHash、outputHash、promptVersion 和 completedAt。AI Gateway 必须实现超时、重试上限、敏感信息拦截、供应商错误映射和调用审计。AI 输出不能直接写正式医嘱或改变审核状态。

## 7. 当前前端开发接口与生产接口的关系

当前本地前端使用：

~~~http
GET  /api/dev/deepseek/status
POST /api/dev/deepseek
~~~

这两个接口仅用于 Vite 本地开发：

- 有服务端环境变量 DEEPSEEK_API_KEY 时，Vite 代理调用 DeepSeek。
- 没有密钥或远端鉴权失败时，前端使用基于已导入事实的本地规则草稿，并明确显示“本地规则草稿”。
- 该开发降级结果不能进入生产数据库，不能作为模型验证证据，不能发送患者。
- 后端正式实现后，前端应改为调用本契约的 /api/pharmacy/medication-education/*，删除对 /api/dev/deepseek 的生产依赖。

本地开发请求体包含 model、temperature、hospitalai_context 和 OpenAI-compatible messages。该请求体只用于本地联调。生产后端必须自行读取事实快照，不能接受前端传入的完整患者事实作为可信来源。

## 8. 前端状态衔接

| 页面状态 | 后端状态 | 允许操作 |
|---|---|---|
| 未选择患者 | 无草稿 | 选择患者、读取工作区 |
| 已选择患者 | 无草稿 | 选择模式、创建草稿 |
| 手写编辑 | draft | 编辑、保存、提交审核 |
| 画像生成中 | generating | 显示加载，禁止重复生成 |
| 已生成草稿 | generated | 编辑、保存、重新生成、提交审核 |
| 待药师审核 | needs_review | 查看、审核、退回 |
| 退回补充 | returned | 原编辑人修改后重新提交 |
| 药师通过 | approved | 查看、按权限创建发送任务 |
| 发送中 | delivery_pending | 查看发送状态 |
| 已发送 | delivered | 查看回执和审计 |
| 生成失败 | generation_failed | 重试或切换手写模式 |

前端必须显示当前草稿 ID、版本、状态、生成来源、事实快照版本、缺失信息和“不发送患者、不改变处方、需药师审核”的边界提示。写操作返回的 traceId 和 auditEventId 必须可追溯。

## 9. JSON Schema 和契约文件

后端实现前应新增并纳入 CI：

~~~text
contracts/medication-education.v1.schema.json
contracts/medication-education-openapi.v1.yaml
~~~

Schema 至少覆盖患者列表、患者工作区、画像、草稿、结构化内容、创建草稿、生成、保存、提交审核、药师审核和通用错误对象。

### 10.2 后端单元和集成测试

- 权限：医生、药师、研究人员、管理员分别验证可读写范围。
- 数据一致性：患者多次就诊不复制主档；草稿绑定正确 encounterId 和事实快照。
- 安全事实：确认过敏和严重不良反应必须进入工作区；前端不能删除或覆盖。
- 缺失事实：剂量、频次、关键检验缺失时，教育内容只能保留待确认。
- 模型失败：超时、401、429、500、空内容、非法 JSON 均进入失败状态，不得伪造成功。
- 幂等：同一 Idempotency-Key 重试只创建一个草稿或审核记录。
- 并发：两个用户同时编辑时必须出现 409，不允许后写覆盖先写。
- 审核：非药师不能批准；被退回后不能直接发送。
- 审计：创建、生成、编辑、提交、审核、发送均有不可删除审计事件。
- 脱敏：发送 AI Gateway 的请求不得出现姓名、身份证号、手机号、住址和完整病案号。

## 11. 后端交付验收标准

后端实现完成后必须同时提交：

1. medication-education-openapi.v1.yaml。
2. medication-education.v1.schema.json。
3. 权限矩阵和测试报告。
4. AI Gateway 调用、超时、重试和敏感信息过滤说明。
5. 持久化模型：草稿、版本、事实快照、生成记录、审核记录、发送任务、审计事件。
6. 正常、缺失、冲突、AI 失败、重复提交、并发冲突和越权测试证据。
7. 前端联调环境地址、模拟身份说明和可复现测试数据版本。

最低验收结论：

- 真实 Core API 可读取患者教育工作区。
- 手写和画像辅助两种模式均能创建和保存草稿。
- AI 生成结果可追溯到事实快照、模型元数据和输出版本。
- 未审核内容不可发送。
- 缺失信息不会被当作正常值。
- 任何写操作可通过 draftId、version、auditEventId、traceId 回溯。
- 前端不持有 DeepSeek 密钥，不直接调用第三方模型接口。
