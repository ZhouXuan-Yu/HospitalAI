> 本文档是医学科研智能平台的产品与开发基线。平台提供科研设计、数据治理、统计分析、图表、报告和论文写作支撑，不保证论文录用、职称评审结果或临床结论成立。任何正式科研成果必须经过伦理、医学、统计及科研管理审核。

## 1. 产品摘要

### 1.1 产品定义

HospitalAI 医学科研智能平台面向医院内非统计专业的科研人员，将分散在 HIS、EMR、LIS、PACS、药学系统及文件中的研究数据，转化为可审核的研究队列、冻结数据集、确定性统计结果、期刊级图表、专业数据分析报告和可复现成果包。

平台不是网页版 SPSS，也不是自动写论文工具。其核心价值是把医学研究中的关键决策、数据来源、变换过程、分析参数、结果和审核意见固化为可追溯流程，使研究团队能够高质量、低重复地完成真实科研项目。

### 1.2 核心价值链

```text
研究意向
  -> 选题与可行性评估
  -> 研究方案和变量规划
  -> 数据授权与提取
  -> 队列构建和数据治理
  -> 数据集冻结
  -> 统计分析计划审核
  -> Python/R 确定性分析
  -> 期刊级图表与结构化结果
  -> 数据分析报告与论文草稿
  -> 医学/统计/科研三级审核
  -> 可复现 ZIP 成果包与版本归档
```

### 1.3 商业交付定位

第一商业版本应完整支撑中文核心期刊和常规 SCI 研究的数据分析与写作准备，并在数据治理、方法学、图表和可复现性方面采用可扩展至高水平期刊的质量门槛。首版不承诺覆盖组学、影像 AI、随机对照试验、多中心联邦研究或自动投稿。

## 3. 背景与问题

### 3.1 当前痛点

1. 医生有研究问题，但难以将其转化为明确的 PICO/PECO、终点、变量和可执行研究方案。
2. 病例筛选依赖人工查询和 Excel 拼接，耗时长、错误多，且无法说明每个样本为何纳入或排除。
3. HIS、EMR、LIS、PACS 和药学数据的编码、时间粒度及缺失语义不同，研究数据难以复用。
4. 统计方法选择和结果解释高度依赖个人经验，容易出现样本量不足、混杂控制不当、过拟合、P 值误用等问题。
5. 本地 DeepSeek R1 能生成文字，但无法单独保证统计正确、引用真实或结果可复现。
6. 常见报告缺少患者级数据、字段字典、置信区间、模型诊断、校准、敏感性分析、代码与审计证据。
7. 数据、图表、报告和论文草稿常由不同人员手工维护，修改后容易失配。

### 3.2 示例文档基线

下列医院现有研究文档作为最低可用水平参考：

- 《儿童感染性腹泻 PCT、白细胞、CRP 的联合应用-规范修订稿》：已包含分组比较、联合模型和 ROC，但平台应补充患者级数据血缘、95% CI、阈值依据、校准、验证、样本量说明和复现代码。
- 《静脉血 EDTA 抗凝采样后立即上机进行全血细胞分析时血小板假性降低原因分析-规范修订稿》：已形成病例构成分析，但平台必须区分病例构成与发生率；研究发生率或危险因素时必须存在总检测人群分母和恰当的多变量分析。

平台生成成果必须优于上述最低基线，但不得对输入数据不支持的结论进行补写。

## 4. 产品目标与成功指标

### 4.1 目标

- 让非统计专业用户在受控模板引导下完成可执行研究设计。
- 将数据筛选、清洗、统计、图表和报告连接为同一条版本化数据链路。
- 让每个统计数字可以追溯到数据集版本、代码版本、参数和运行环境。
- 让医院能够在内网完成敏感数据处理和本地模型调用。
- 形成可复制到不同医院的数据适配、模板实施和交付模式。

### 4.2 SMART 目标

| 编号 | 目标 | 首期验收指标 |
|---|---|---|
| O1 | 打通科研全流程 | 3 类研究模板均能从立项运行到审核与 ZIP 导出 |
| O2 | 降低人工处理 | 结构化数据导入后的标准项目准备时间较纯人工流程降低 50% 以上 |
| O3 | 提高可追溯性 | 正式结果、图表、报告的来源追踪覆盖率达到 100% |
| O4 | 保证方法学门槛 | 所有正式项目均完成 SAP 审核、数据冻结和统计审核 |
| O5 | 形成试点价值 | 单院 2 至 3 个科室完成 5 至 10 个真实项目验证 |
| O6 | 控制安全风险 | 未授权访问、直接标识泄露和越权发布事件为 0 |

### 4.3 非目标

- 不保证投稿录用、影响因子或职称结果。
- 不让 AI 自由生成患者数据、统计数字、参考文献或因果结论。
- 不让 AI 直接执行任意数据库 SQL。
- 不替代伦理审批、研究注册、统计审核、医学审核或作者署名决策。
- 不把合成数据结果包装为真实科研证据。
- 不将一次研究结果自动发布为临床规则或处方决策依据。

## 5. 用户与权限

| 用户 | 首要任务 | 默认权限 |
|---|---|---|
| 临床医生/药师/检验人员 | 提出课题、定义临床问题、解释结果、撰写内容 | 创建项目、申请数据、编辑方案、查看获授权数据 |
| 青年医师/研究助理 | 整理变量、处理质控问题、完善文稿 | 在项目授权范围内编辑，不可终审 |
| 项目负责人 PI | 冻结研究设计、确认临床结论、提交审核 | 项目级管理和一级审核 |
| 统计师 | 审核 SAP、模型诊断和统计结论 | 锁定/驳回统计方案与运行结果 |
| 医学负责人 | 审核临床合理性、局限和结论 | 医学终审，不可篡改统计值 |
| 科研管理人员 | 核验伦理、立项、成果归档与发布条件 | 项目治理和发布门禁 |
| 数据管理员 | 数据源、字段映射、脱敏、授权与质量 | 不参与医学结论审核 |
| 系统管理员 | 用户、角色、配置、任务和运维 | 不可绕过专业审核或删除审计 |

权限必须同时校验用户、角色、科室、项目、数据域、研究目的、伦理状态和有效期。前端角色切换仅供开发演示，正式权限以服务端授权为准。

## 6. 产品原则

1. **研究问题先于算法**：先确定研究设计、终点、变量和偏倚，再选择方法。
2. **数据版本先于结果**：未冻结的数据集不得产生正式结果。
3. **确定性计算先于 AI 文本**：统计值由审核过的 Python/R 流程计算，AI 只解释结构化结果。
4. **证据不足即停止**：没有分母、对照、样本量或关键变量时，系统必须阻断不成立的分析。
5. **全链路可追溯**：原始数据、映射、清洗、队列、SAP、运行、图表、报告和审核均留痕。
6. **版本不可覆盖**：已冻结或已发布版本只追加新版本，不原地修改。
7. **人类承担专业责任**：AI 不成为作者、审核人或结论责任主体。
8. **内网最小暴露**：敏感数据默认不离院、不进入未经批准的云模型。

## 8. 端到端业务流程

### 8.1 主状态机

```text
草稿
 -> 可行性评估中
 -> 方案待审核
 -> 数据授权中
 -> 数据提取中
 -> 队列构建中
 -> 质控整改中
 -> 数据集已冻结
 -> SAP 待审核
 -> 分析运行中
 -> 结果待统计审核
 -> 报告待医学审核
 -> 待科研管理发布
 -> 已发布/已归档
```

任何上游研究设计、字段映射、队列逻辑、缺失策略或 SAP 的变化，都必须使相关下游结果失效并触发重新运行。被驳回状态必须记录原因、责任人和整改版本。

### 8.2 强制门禁

| 门禁 | 阻断条件 | 放行角色 |
|---|---|---|
| 立项门禁 | 问题不明确、无临床价值、数据不可得 | PI + 医学负责人 |
| 数据门禁 | 无授权/伦理依据、存在直接标识、来源不明 | 数据管理员 + 科研管理 |
| 冻结门禁 | 严重质量问题、关键变量缺失、纳排不可复现 | PI + 数据管理员 |
| 分析门禁 | SAP 未审核、样本量不足、模型不适用 | 统计师 |
| 报告门禁 | 统计未审核、结论超出结果、引用未核验 | 统计师 + 医学负责人 |
| 发布门禁 | 伦理/注册/作者/数据声明不完整 | 科研管理人员 |

## 10. 功能需求

### 10.1 项目中心 `MRP-PROJ`

**输入**：项目名称、研究类型、科室、负责人、协作者、计划周期、目标期刊层次。

**功能**：创建/复制/归档项目；按状态、科室、负责人筛选；展示进度、风险、审核待办和最近制品；支持模板创建。

**输出**：`ResearchProject`、项目成员、里程碑和唯一项目编号。

**验收**：用户只能看到授权项目；归档不删除数据；项目主页可定位所有阻断项和下一步操作。

### 10.2 选题与可行性 `MRP-TOPIC`

**选题来源**：临床难题、药物疗效/安全性、检验流程、院内质量数据、指南证据缺口、既往研究复核。

**评价维度**：创新性、临床价值、数据可得性、方法可行性、样本量、伦理风险、预计周期和目标期刊匹配度。

**功能**：PICO/PECO 引导；研究类型识别；初步变量和终点建议；可用数据域匹配；样本量粗估；相似院内项目查重；风险清单；专家评审。

**输出**：版本化研究问题、可行性评分、数据需求清单、风险与“继续/调整/停止”结论。

**模板示例**：

1. 疾病风险预测：在目标人群中，哪些基线因素与指定时间窗结局相关？
2. 药物比较：在明确适应证患者中，药物 A 与药物 B 的有效性和安全性是否不同？
3. 诊断标志物：指标 A、B、C 单独及联合对目标疾病的诊断效能如何？

### 10.3 研究方案设计 `MRP-PROTOCOL`

**输入**：研究问题、设计类型、人群、时间窗、暴露/干预、对照、终点、协变量、偏倚和伦理信息。

**功能**：协议模板；主要/次要终点；索引日期；洗脱期、观察期和随访期；纳排标准；样本量估算参数；伦理/注册状态；版本差异。

**输出**：`ProtocolVersion` 和机器可读字段需求。

**规则**：主要终点、研究人群和时间零点未定义时，不允许进入数据提取。

### 10.4 数据源与权限 `MRP-DATA-AUTH`

**数据源**：HIS、EMR、LIS、PACS、药学系统、随访系统、数据仓库、Excel/CSV/JSON。

**功能**：数据目录浏览；字段可用性说明；授权申请；研究目的和期限；伦理材料绑定；最小字段申请；脱敏策略预览。

**输出**：`DataAccessGrant`、授权范围、到期时间和审批记录。

**规则**：权限到期后停止新任务；历史制品按留存策略处理；直接身份字段默认禁止进入分析区。

### 10.5 数据导入与提取 `MRP-INGEST`

**在线链路**：通过只读视图、数据仓库、标准接口或医院批准的同步区提取，不直写业务系统。

**文件链路**：Excel、CSV、JSON 通过正式导入器进入，同一验证链路也用于合成数据演示；代码中不得写死研究记录。

**处理**：文件类型与大小、病毒扫描、公式注入、编码、字段类型、日期、单位、代码集、重复、范围和引用完整性校验；生成文件 SHA-256。

**输出**：`ImportBatch`、原始只读快照、标准化暂存表、字段映射、错误报告和血缘记录。

**失败规则**：错误定位到文件/工作表/行/列；不得部分发布不完整批次；重复上传通过哈希和幂等键识别。

### 10.6 队列构建器 `MRP-COHORT`

**输入**：协议版本、标准化数据、纳排条件、时间窗和代码集。

**功能**：可视化条件组；事件先后关系；首次/再次用药；持续暴露；最短随访；排除原因；样本计数预览；患者级纳排轨迹。

**输出**：`CohortDefinitionVersion`、纳入集、排除日志和流程图数据。

**规则**：自然语言可辅助生成条件草稿，但必须转为受控表达式并由用户确认；AI 不直接执行自由 SQL。

### 10.7 变量与终点 `MRP-VARIABLE`

**输入**：字段、临床定义、单位、代码集、观察窗、派生公式和缺失语义。

**功能**：变量字典；原始/派生/结局/协变量分类；单位换算；正常范围来源；多次测量聚合；结局判定算法；映射审核。

**输出**：`VariableDefinitionVersion`、`EndpointDefinitionVersion` 和转换规则。

**规则**：每个变量必须包含名称、业务定义、类型、单位、来源、时间窗、允许值、缺失编码和版本。

### 10.8 数据质量 `MRP-DQ`

**质控维度**：完整性、唯一性、有效性、一致性、及时性、分布合理性和跨表引用完整性。

**功能**：缺失矩阵、异常值、重复、时间逻辑、单位冲突、编码异常、数据漂移、终点可判定率；问题分派与整改。

**缺失处理**：区分未采集、不适用、未知、系统失败和失访；支持完整病例、多重插补或模型内处理，但策略必须在 SAP 中预设。

**输出**：`DataQualityReport`、问题清单、修复记录和冻结建议。

### 10.9 数据集冻结 `MRP-FREEZE`

**功能**：冻结前预检；生成数据集版本、记录数、字段数、队列版本、变量版本、输入哈希和质量摘要；版本比较；撤销申请。

**输出**：不可变 `DatasetVersion`。

**规则**：冻结后不允许编辑；修改必须形成新版本；撤销不删除原版本；分析只引用冻结版本。

### 10.10 统计分析计划 `MRP-SAP`

**内容**：研究假设、分析集、描述方法、效应量、显著性水平、置信区间、多重比较、混杂控制、缺失策略、亚组、敏感性分析、模型诊断和软件环境。

**算法选择规则**：

| 问题 | 推荐方法 | 必查条件/指标 |
|---|---|---|
| 两组连续变量 | t 检验或 Mann-Whitney U | 分布、方差、效应量与 CI |
| 分类变量 | 卡方或 Fisher | 期望频数、风险差/OR/RR 与 CI |
| 二分类结局 | Logistic 回归 | 共线性、拟合、校准、OR 与 CI |
| 时间结局 | KM、log-rank、Cox | 风险集、删失、PH 假设、HR 与 CI |
| 诊断预测 | ROC、DeLong、校准、DCA | AUC、CI、阈值、敏感度、特异度 |
| 观察性药物比较 | PSM/IPTW + 回归 | positivity、平衡 SMD、权重诊断 |
| 机器学习预测 | LASSO、随机森林等 | 嵌套交叉验证、过拟合、校准、外部验证 |
| 一致性/方法比较 | Kappa、ICC、Bland-Altman | 适用尺度、CI、一致性界限 |

**输出**：已审核 `StatisticalAnalysisPlanVersion`。

### 10.11 分析运行与诊断 `MRP-ANALYSIS`

**计算引擎**：Python 负责数据工程、常规统计和机器学习；R 负责成熟医学统计和专用图表。所有正式任务由预注册工作流执行。

**功能**：参数确认；异步运行；进度、日志和资源监控；失败重试；结构化结果；模型诊断；横向运行比较。

**验证**：训练/验证集隔离、交叉验证、时间外验证或外部验证按研究类型配置；禁止使用测试集调参。

**输出**：`AnalysisRun`、结构化统计结果、模型对象、诊断、软件环境、代码与结果哈希。

**规则**：同一数据、代码、依赖、随机种子和参数必须产生可复核结果；AI 不计算或改写正式数值。

### 10.12 科研图表工作室 `MRP-FIGURE`

**首版模板**：基线表、纳排流程、箱线/小提琴、分组点图、ROC、PR、KM 风险表、森林图、亚组森林图、校准、DCA、相关热图、缺失图、Bland-Altman、混淆矩阵、特征重要性、SHAP、分组柱图、趋势图、敏感性分析等至少 20 类。

**风格**：通用医学期刊、Nature Portfolio、JAMA、Lancet 和自定义模板。期刊名称仅表示预设样式，不表示期刊认可。

**输出**：PDF/SVG 矢量文件、600 dpi TIFF、PNG 预览，可选 EPS；同时保存图表数据、说明、统计关联和生成参数。

**规则**：用户可调整标题、标签、尺寸、配色和布局，不得手工改写计算值；任何图表都必须关联分析运行。

### 10.13 数据分析报告 `MRP-REPORT`

**章节**：标题页、结构式摘要、背景、研究问题、设计、人群与数据源、变量与终点、统计方法、数据质量、结果、图表、讨论、偏倚、局限、结论、伦理、数据可用性、软件与复现、审核记录。

**结果规范**：同时报告样本量、效应量、95% CI、P 值（适用时）、缺失情况和临床意义；不得只依据 `P < 0.05` 生成结论。

**输出**：DOCX、PDF、Markdown/HTML 和结构化 `report.json`。

**规则**：报告中的每个表、图和关键数值可点击追溯到统计结果；证据不足时明确显示“无法支持该结论”。

### 10.14 论文写作工作台 `MRP-MANUSCRIPT`

**功能**：IMRaD 结构；目标期刊要求清单；引用占位与核验；表图编排；作者贡献、利益冲突、数据声明和报告清单；双语版本后续支持。

**AI 能力**：基于已审核协议和结果生成文字草稿、润色、压缩摘要和一致性检查。

**禁止**：生成虚假参考文献、修改统计值、隐瞒局限、将相关性写成因果或生成未经数据支持的医学建议。

### 10.15 审核与协作 `MRP-REVIEW`

**审核顺序**：PI/项目负责人 -> 统计师 -> 医学负责人 -> 科研管理发布检查。

**功能**：段落/表图批注、问题分派、修改前后差异、电子确认、驳回与重提、逾期提醒、审核证据导出。

**规则**：审核意见只追加；审核人身份来自正式认证；管理员不可伪造审核人或跳过阻断项。

### 10.16 成果导出与归档 `MRP-EXPORT`

**成果包目录**：

```text

protocol/
data/raw-source-manifest.json
data/analysis-dataset.csv
data/analysis-dataset.xlsx
data/variable-dictionary.csv
data/inclusion-exclusion-log.csv
quality/
sap/
code/python/
code/r/
environment/
results/
figures/pdf-svg-tiff-png/
report/
manuscript/
reviews/
audit/
checksums/SHA256SUMS
```

**功能**：发布预检、去标识扫描、导出授权、后台生成、哈希校验、下载审计、长期归档和版本回读。

**规则**：三级审核前只能导出带水印的工作包；合成数据必须永久标注“仅供演示验证”；失败任务不得产生可发布包。

### 10.17 文献、模板与方法中心 `MRP-KNOWLEDGE`

**功能**：研究模板、变量模板、算法说明、报告清单、期刊样式、真实文献元数据和医院方法学规范；版本发布、替换和撤回。

**规则**：未核验文献不得进入正式报告；模型生成的引用只能作为待核验候选；所有方法模板需由统计负责人发布。

### 10.18 系统管理 `MRP-ADMIN`

**功能**：组织/科室/角色、数据源、代码集、字段映射、模型网关、计算资源、任务队列、审计、授权、备份、许可证和健康状态。

**规则**：系统配置变更需要审计；高风险配置双人复核；日志中不得记录患者直接标识、密钥或完整研究数据。

## 11. AI 智能体要求

### 11.1 本地模型定位

平台通过统一模型网关接入医院本地 DeepSeek R1。模型用于：

- 将自然语言研究意向整理为结构化草稿。
- 建议变量、偏倚、缺失项和方法候选。
- 解释统计方法和模型诊断。
- 根据确定性结果生成报告或论文文字草稿。
- 执行文稿一致性、结论越界和引用完整性检查。

### 11.2 驾驭工程

- 任务拆解为受控步骤，每步使用固定输入/输出 Schema。
- 检索范围限定为已发布知识和项目已授权资料。
- 关键字段通过规则与 Schema 校验，失败时拒绝进入下游。
- 低置信度、资料冲突和证据不足必须显式标记。
- 记录模型、参数、提示模板、知识版本、输入摘要和输出版本。
- 模型不可直接访问数据库、文件系统、统计运行环境或发布状态。

### 11.3 AI 质量评测

建立不少于 100 个基准案例，覆盖研究设计识别、变量建议、方法选择、结果解释、引用真实性、隐私泄露和越界结论。上线门槛由医学、统计和安全评审共同确定，模型升级必须回归评测。

## 13. 接口与集成要求

### 13.1 接口原则

- OpenAPI 是前后端业务契约的机器可读权威。
- 每个页面必须有独立 Markdown 接口文档，描述用途、角色、字段、状态机、错误码、幂等、并发、审计和联调示例。
- 写操作使用幂等键；版本更新使用乐观锁；长任务返回任务 ID。
- 错误响应包含稳定错误码、用户可读信息、关联 ID 和可否重试标识。
- 文件上传、分析、报告和导出采用可靠任务表与 Worker，不依赖浏览器长连接完成。

### 13.2 适配器

- `HisResearchConnector`：人口学、就诊、诊断、医嘱和费用。
- `EmrResearchConnector`：病历结构化字段及经批准的文本抽取结果。
- `LisResearchConnector`：检验项目、结果、单位、参考范围和时间。
- `PacsMetadataConnector`：影像检查元数据；首版不处理影像算法。
- `PharmacyResearchConnector`：药品目录、用药暴露、审核和不良事件。
- `ResearchFileImporter`：Excel/CSV/JSON 正式导入。

适配器只负责认证、字段映射和传输，不改变内部研究模型和质量门禁。

## 14. 安全、合规与伦理

- 医院内网 Linux x86_64 容器部署；默认无公网依赖。
- 统一身份认证，支持医院 SSO/OIDC 适配；服务端 RBAC + ABAC。
- 传输和存储加密；密钥进入医院批准的密钥管理方案。
- 研究区使用去标识数据；身份映射表与分析数据物理或逻辑隔离。
- 下载、导出、查看敏感字段、授权和模型调用全部审计。
- 数据留存、销毁、备份和恢复由医院制度配置；审计与已发布制品不得由普通管理员删除。
- 上传文件执行白名单、限额、恶意内容、公式注入、路径穿越和压缩炸弹防护。
- 研究必须绑定伦理/豁免/立项状态；状态变化触发权限与发布门禁。
- 正式引用必须可定位到真实文献元数据；禁止模型伪造 DOI、作者、期刊或结论。

## 15. 非功能需求

### 15.1 性能

| 场景 | 首版目标 |
|---|---|
| 普通页面读取 | P95 <= 2 秒（不含长任务） |
| 10 万行结构化文件校验 | 基线服务器 5 分钟内完成 |
| 100 万行队列预览 | 30 秒内返回估算或异步精确计数 |
| 标准统计任务 | 显示进度、可取消、可重试；具体 SLA 按模板基准确定 |
| 成果包生成 | 10 GB 以内任务异步执行并支持断点与校验 |

### 15.2 可用性与恢复

- 生产目标可用性不低于 99.5%，计划维护除外。
- 数据库每日全量、持续增量或等效备份；制品库按医院策略多副本。
- 试点目标 RPO <= 24 小时、RTO <= 8 小时；商业版目标 RPO <= 1 小时、RTO <= 4 小时。
- 每半年执行恢复演练，验证数据库、制品、审计和配置可回读。

### 15.3 可观测性

记录关联 ID、任务耗时、数据量、失败阶段、重试次数、资源使用、模型版本、数据/代码/结果哈希。提供服务健康、队列积压、失败率、存储容量和授权到期告警。

### 15.4 兼容性与可访问性

- 支持医院批准的 Chromium 内核浏览器最近两个稳定大版本。
- 桌面优先，1366x768 和 1920x1080 无重叠、横向异常滚动或关键操作遮挡。
- 键盘操作、焦点、对比度和错误提示满足医院业务可用性要求。

## 16. 技术产品约束

- 前端：Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus。
- 业务核心：Spring Boot 模块化单体，负责权限、状态、审计、项目和制品事实。
- AI/分析：FastAPI 服务编排 Python/R Worker；AI 与统计执行隔离。
- 数据：PostgreSQL + pgvector；原始附件和成果使用可替换 BlobStorage。
- 异步：PostgreSQL 可靠任务表；首版不引入 Kafka、RabbitMQ 或 Redis 作为必需组件。
- 部署：Docker Compose 支持试点，商业版提供可扩展容器部署方案；CPU 必需，GPU 可选。

## 18. 测试与验收

### 18.1 功能验收场景

1. 诊断效能项目从 PICO 到联合 ROC、校准、报告和 ZIP 完整运行。
2. 老年患者两种常用药比较项目完成队列、IPTW/PSM、KM/Cox、亚组和敏感性分析。
3. 实验室异常项目能识别缺少总人群分母并阻断“发生率”结论。
4. 数据存在重复、单位冲突、异常日期、关键缺失和错误编码时准确定位且不可冻结。
5. 修改纳排或 SAP 后旧结果自动失效，重新运行生成新版本。
6. AI 服务不可用时，数据治理、统计运行和成果追溯仍可工作，文字草稿显示降级。
7. 越权用户无法查看数据、审核或导出；管理员无法绕过阻断。
8. ZIP 解压后清单、哈希、代码、数据、图表、报告和审核记录一致。

### 18.2 质量验收

- 需求覆盖率：P0 需求 100%，P1 需求 >= 95%。
- 契约测试：OpenAPI、Schema、前后端类型和页面接口文档一致。
- 统计金标准：标准测试数据与已确认 Python/R 或人工基准结果在预设容差内一致。
- 安全：SAST、依赖、镜像、密钥、上传、权限和常见 Web 漏洞扫描无未接受的高危问题。
- 性能：核心数据量级压测达到第 15 章目标，无数据错乱或任务重复发布。
- 一致性：数据库、制品清单、哈希、报告数值和图表来源可双向追溯。
- 兼容性：1366x768、1920x1080 及批准浏览器通过关键流程验证。
- 容灾：恢复后项目状态、冻结数据、分析结果、制品和审计完整。
- 对抗审查：覆盖虚假引用、提示注入、统计越界、结论夸大、权限绕过和隐私泄露。

### 18.3 最终验收证据

## 20. 优先级

### P0：首个可交付版本

- 项目、选题、协议、正式文件导入、队列、变量、质控、冻结、SAP、确定性分析。
- 三个研究模板、至少 20 个图表模板、报告、三级审核、ZIP 和审计。
- 本地 DeepSeek 网关与失败降级。
- 页面级接口文档、OpenAPI、部署、备份恢复和安全基线。

### P1：单院试点增强

- HIS/EMR/LIS/药学适配器、数据目录、授权流程和增量同步。
- 外部/时间外验证、运行资源配额、模板运营和机构级指标。
- 双语报告和更多期刊样式。

### P2：规模化与高阶科研

- 多中心、联邦分析、组学、影像、前瞻性研究、Meta 分析和智能选题运营。

## 21. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 医院数据质量低或语义不统一 | 项目不可分析 | 数据目录、字段映射、质量门禁和模板化整改 |
| 用户期待“一键发论文” | 商业和合规风险 | 产品文案、合同、门禁和人工审核明确边界 |
| 本地模型质量不稳定 | 草稿错误或幻觉 | 结构化任务、受控检索、评测、降级和人审 |
| 统计模板被误用于不适用数据 | 错误结论 | SAP 审核、适用性检查、诊断和阻断规则 |
| 隐私或越权 | 严重安全事件 | 最小权限、去标识、隔离、审计和导出审批 |
| 定制化拖垮产品 | 无法复制交付 | 内部统一模型、适配器边界和版本化模板 |
| 图表漂亮但方法不成立 | 误导科研人员 | 先分析门禁再允许正式图表和报告 |

## 22. 当前可实现边界

当前工程可以先完成基于 Excel/CSV/JSON 的前端演示和正式接口契约，通过合成数据导入跑通全流程；该能力只证明交互、状态、制品和接口形态可用。真实科研交付还必须实现服务端持久化、Python/R 确定性分析、医院数据适配、权限、审计、脱敏、三级审核、制品签名和真实项目验证。不得将浏览器端生成的演示报告或合成数据成果认定为可投稿成果。

## 23. 开发文档交付要求

开发前必须进一步拆分并冻结以下文档：

1. 页面级交互与字段规格。
2. 每页独立 API 接口文档及 OpenAPI。
3. 内部研究统一模型与 JSON Schema。
4. 三类研究模板的医学与统计方法规范。
5. 数据映射、质量规则和代码集规范。
6. Python/R 统计工作流和金标准测试集。
7. Scientific Figure Engine 模板规范。
8. 报告、论文草稿和 ZIP 成果包规范。
9. RBAC/ABAC、伦理、脱敏和审计规范。
10. 部署、监控、备份、恢复、升级和验收手册。

各开发任务必须在需求追踪矩阵中绑定 PRD 编号、设计文档、接口、数据库对象、测试用例和验收证据，禁止仅以“页面完成”或“接口可调用”作为端到端完成标准。

## 24. 发布判定

只有同时满足以下条件，产品才可判定达到单院上线试点门槛：

- P0 功能和三类纵向项目全部通过。
- 真实数据链路经过医院授权并完成去标识验证。
- 统计金标准、方法审核和图表追溯通过。
- 权限、安全、性能、数据一致性、兼容性和恢复演练通过。
- 所有高危问题和阻断问题完成闭环。
- 医学、统计、信息、科研管理和产品负责人联合签署验收结论。

未达到上述条件时，只能标记为开发演示、测试环境或受限试点，不得宣称为可正式支撑论文发布的生产系统。
